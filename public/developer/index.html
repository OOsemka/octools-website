Developer Guide

Build, package, and publish your own OCT extension.

OCT Conventions

Naming

Use oct-<name> everywhere: plugin ID, directory, container image, ConsolePlugin CR, and catalog entry.

FieldPatternExample
Plugin IDoct-<name>oct-baremetal
Imagequay.io/<org>/oct-<name>:<tag>quay.io/myorg/oct-baremetal:1.0.0-ocp4.22
i18n namespaceplugin__oct-<name>plugin__oct-baremetal
CSS prefixModule-specificbmh-, hw-

Versioning

OCT uses two axes: extension semver and OpenShift minor. Image tags always combine both:

<semver>-ocp<major.minor>

# Examples:
1.0.0-ocp4.22
1.0.0-ocp4.21
0.1.1-ocp4.22

Always publish both OpenShift minor tags (same digest if bits match). Never catalog a (version, minor) unless the exact combined tag is public.

PatternFly

Use PatternFly 6 only. Import from @patternfly/react-core ^6. Do not import PatternFly CSS (the console host provides it).

Community Disclaimer

Include a CommunityDisclaimer component on all tool pages:

"Community project. Not officially supported by Red Hat."

Start from the Template

Fork oct-hello-world and follow these steps:

  1. Rename the plugin ID in package.json → consolePlugin.name
  2. Update routes in console-extensions.json
  3. Build your page components in src/
  4. Verify the build: 
    yarn install
yarn build
  5. Build the container: 
    podman build -t quay.io/<org>/oct-<name>:<semver>-ocp4.22 .
  6. Push to a public registry (no pull secret for community Add): 
    podman push quay.io/<org>/oct-<name>:<semver>-ocp4.22

Catalog PR

To list your tool in the storefront catalog, submit a PR to oct-storefront adding your tool to catalog/community.yaml:

- metadata:
    name: oct-your-tool
  spec:
    displayName: "Your Tool"
    description: "What it does"
    category: Compute          # Compute | Storage | Network | Management
    consolePlugin: oct-your-tool
    href: /community-tools/compute/your-tool
    defaultChannel: stable
    versions:
      - version: "1.0.0"
        channel: stable
        openshift: ["4.21", "4.22"]
        image: quay.io/org/oct-your-tool:1.0.0-ocp4.22
        gitRef: v1.0.0

Also create a deploy bundle YAML at catalog/deploy/oct-your-tool.yaml and register it in BUNDLED_DEPLOY. The bundle must include every resource the extension needs: Namespace, Deployment, Service, ConsolePlugin, RBAC, PVCs, etc.

External Module Path

If you don't want to submit a catalog PR, users can still install your tool:

  1. Click Add external extension in the storefront
  2. Paste a CommunityTool YAML manifest
  3. The extension gets an orange badge, and stats stay cluster-local

See oct-hello-external for a working example.
